# 글쓰기 안내

## 글 한 편 올리기

홈 화면의 **이어서 쓰기**에서 최근 초안을 바로 열 수 있습니다. 왼쪽 위
**Blog Studio**를 누르면 현재 내용을 저장한 뒤 홈으로 돌아갑니다.
글 설정은 필요할 때 여는 패널이며, 닫기 버튼이나 `Esc`로 편집에 돌아갑니다.

1. **새 글 쓰기**를 누릅니다. 빈 글, 논문 리뷰, 개발 노트, 오늘 배운 것
   템플릿을 선택할 수 있습니다.
2. 제목과 본문을 작성합니다. **시각 편집**에서는 도구 모음으로 서식을 적용하고,
   **Markdown**에서는 원문을 편집합니다.
3. 이미지를 본문에 붙여넣거나 끌어 놓습니다. **삽입 → 이미지 넣기**에서 여러 장을
   선택할 수도 있습니다. PNG, JPEG, GIF, WebP, AVIF를 한 장당 12MB까지 받습니다.
4. **글 설정**에서 카테고리, 태그, 날짜, 주소 이름, 대표 이미지, 공개 여부 등을
   정합니다. 새 글의 주소 이름은 비워두면 제목에서 자동 생성됩니다.
5. **발행 준비**에서 대상 파일과 경고를 확인하고 원하는 저장 방식을 선택합니다.

| 선택 | 실행되는 작업 |
| --- | --- |
| 파일로 저장 | `_posts`와 글에 사용하는 새 이미지를 저장 |
| 저장 + Git 커밋 | 파일 저장 후 이 글과 이미지의 변경을 로컬 Git 커밋으로 기록 |
| 저장 + GitHub 전송 | 파일 저장과 커밋 후 `origin`의 현재 브랜치로 push |

자동 저장과 `Ctrl/⌘+S`는 **로컬 초안 저장**입니다. 발행 준비에서 확인하기 전에는
블로그 원본 파일을 바꾸거나 GitHub로 전송하지 않습니다. `published: false`인
기존 글은 공개 설정을 직접 바꾸기 전까지 비공개 상태를 유지합니다.

GitHub 전송 완료 후 사이트에 반영되기까지 시간이 걸릴 수 있습니다.
**작업 메뉴 → GitHub · 업데이트 → 사이트 게시 상태**에서 전송한 커밋의 실제 게시 완료를
확인합니다. 실패한 Actions 작업은 로그를 열거나 다시 실행할 수 있습니다.
편집기는 Pages 설정이나 배포 워크플로를 변경하지 않습니다.

## 도구 모음과 제목

본문 도구 모음은 스크롤해도 화면 위에 남습니다. **본문 / 제목 1~6**,
굵게·기울임·밑줄, 문단 정렬은 자주 쓰는 도구로 바로 표시합니다.
나머지는 **서식 · 삽입 · 편집 · 문서** 메뉴로 묶었습니다. 메뉴 바깥을 누르거나
`Esc`로 닫을 수 있으며, 메뉴를 열어도 본문에서 선택한 영역을 유지합니다.
글과 무관한 템플릿·백업·GitHub 연결·앱 업데이트는 상단의 **작업 메뉴**에 있습니다.
작은 화면에서는 **•••** 버튼으로 표시되며 홈에서도 사용할 수 있습니다.

제목 종류를 고르면 커서가 있는 문단이나 선택한 문단의 제목 수준을 바꿉니다.
다시 **본문**을 선택하면 일반 문단으로 돌아갑니다. 정렬과 글자 서식을 유지하며,
`Ctrl/⌘ + Z`로 되돌릴 수 있습니다. 글 전체의 제목은 상단의 글 제목 입력란에서 편집합니다.

## 문단 정렬

**시각 편집**에서 **왼쪽 정렬 / 가운데 정렬 / 오른쪽 정렬**을 누릅니다.

- 드래그한 글이 없으면 본문의 일반 문단과 제목 전체에 적용합니다. 커서만 놓인
  경우에도 전체 정렬입니다.
- 글을 드래그해 선택하면 선택에 포함된 문단과 제목만 정렬합니다. 정렬은 글자
  일부가 아니라 해당 글자가 속한 문단 단위로 적용합니다.
- 정렬된 문단에서 `Enter`를 누르면 새 문단에도 같은 정렬이 이어집니다.
- 목록·표·인용문·코드의 구조는 바꾸지 않습니다. 이 블록을 직접 선택한 경우에는
  지원 범위를 안내합니다.

버튼 옆의 적용 범위와 강조 표시로 전체/선택 영역 및 정렬 상태를 확인할 수 있습니다.
정렬은 자동 저장되며 초안을 다시 열거나 파일로 저장한 뒤에도 유지됩니다.
`Ctrl/⌘ + Z`로 되돌릴 수 있습니다.

Markdown 모드에서는 정렬 버튼이 비활성화됩니다. 정렬된 문단은 HTML로 저장되며
Markdown 미리보기에서도 정렬을 확인할 수 있습니다. 기존 글을 시각 편집으로 바꿀 때는
원래 안내대로 수식·Liquid·복잡한 HTML의 변환 가능성을 확인하세요.

## 글쓰기와 이미지 도구

- **서식 → 글자색 / 형광펜**, **밑줄**: 시각 편집에서 선택한 글자에 적용하며 되돌리기를 지원합니다.
  서식은 Markdown 파일 안의 HTML로 유지됩니다. 코드는 서식 적용 대상에서 제외합니다.
- **편집 → 찾기·바꾸기**: 현재 본문에서 검색하고 한 곳 또는 전체를 바꿉니다. 대소문자 구분을
  선택할 수 있고, Markdown과 시각 편집 양쪽에서 되돌릴 수 있습니다.
- **편집 → 목차·문단 이동**: 제목을 눌러 본문으로 이동하거나 블록을 위·아래로 옮깁니다.
  시각 편집에서는 끌어서 순서도 바꿀 수 있습니다.
- **삽입 → 이미지 다듬어 넣기 / 선택한 이미지 편집**: 파일을 선택하거나 본문의 이미지를 선택한 뒤 자르기·크기·품질·형식을
  조절합니다. 설명을 달거나 수정할 수 있으며, 편집 결과는 새 이미지로 저장합니다.
  외부 서버의 이미지는 해당 서버의 접근 정책에 따라 Canvas 편집이 제한될 수 있습니다.
  큰 정지 이미지는 업로드 전에 자동 최적화하며 GIF 등 애니메이션은 자동 변환하지 않습니다.
- **삽입 → 링크 카드**: URL의 제목·설명·이미지를 가져와 수정한 후 본문에 넣습니다.
  **내 글 링크**로 기존 글을 검색해 연결할 수도 있습니다. 카드 표현은 실제 테마의
  인용문·이미지 스타일을 따릅니다.
- **삽입 → 일반 링크 / 이미지 주소**: 웹 주소나 블로그 내부 경로를 직접 넣습니다.
  Markdown 모드에서도 사용할 수 있습니다. 본문에서 `Ctrl/⌘ + K`로 링크 창을 열 수 있습니다.

## 내 템플릿과 변경 비교

**작업 메뉴 → 내 템플릿·문구**에서 현재 글을 템플릿으로 저장하거나 선택한 내용을 재사용 문구로
보관합니다. 템플릿은 새 초안을 만들고, 문구는 커서 위치에 들어갑니다. 수정·삭제가
가능하며 두 종류 합계 100개, 항목별 내용 4MB까지 보관합니다.

**문서 → 기록 → 변경 비교**에서 선택한 버전과 현재 저장된 초안의 본문·제목·글 설정 차이를
확인합니다. 비교만으로 내용은 바뀌지 않습니다. 복원하려면 기존 **복원** 버튼을 사용합니다.

## 실제 테마 미리보기

**문서 → 테마 미리보기**는 블로그를 임시 폴더로 복사한 뒤 현재 초안을 실제 Jekyll로 빌드합니다.
원본 글을 발행하지 않으며 PC·태블릿·모바일 폭을 바꿔 볼 수 있습니다. Ruby/Jekyll은
실행 파일에 포함하지 않습니다. 처음에는 메뉴의 설치 안내에 따라 Ruby와 Bundler를
준비한 뒤 **환경 준비**로 블로그의 Gemfile 의존성을 설치하세요. 로컬 gem 캐시는
`.blog-studio` 안에 저장합니다. 테마가 요구하는 시스템 라이브러리는 별도로 필요할 수 있습니다.

## 백업과 컴퓨터 간 초안 동기화

**작업 메뉴 → 백업·동기화 → 전체 ZIP 내려받기**는 `_posts`, `assets/images`, 초안, 저장 기록,
임시 첨부 이미지와 내 템플릿을 보관합니다. ZIP 최대 128MB, 압축 해제 후 256MB,
파일 10,000개를 지원합니다. Git 이력·테마·설정 전체를 복제하는 기능은 아닙니다.
복원할 때 기존 파일은 덮어쓰지 않습니다. 내용이 다른 초안은 별도 복사본으로,
충돌 파일은 `.blog-studio/backups/import-*`에 남깁니다.

**비공개 초안 동기화**는 GitHub 계정에 `blog-studio-drafts` 비공개 저장소를 만들거나
기존 비공개 저장소를 사용합니다. 같은 블로그 `repository` 설정(없으면 URL)을
사용하는 컴퓨터끼리 초안·첨부·기록·템플릿을 합칩니다. 최대 32MB ZIP을 지원하고,
내용이 다르면 양쪽을 보존합니다. **삭제는 다른 컴퓨터로 전파하지 않으므로** 원격에
남은 초안은 다시 가져올 수 있습니다. 공개된 동명 저장소에는 초안을 보내지 않습니다.
개인 액세스 토큰을 쓰는 경우 해당 비공개 저장소 접근 권한과 저장소 생성 권한이
필요합니다. 자동 동기화 대신 사용자가 버튼을 눌러 실행하는 방식입니다.

## GitHub 연결과 앱 업데이트

시작 창의 **GitHub에서 블로그 가져오기**에서 로그인한 뒤 저장소와 빈 대상 폴더를
선택하면 복제할 수 있습니다. Git은 별도 설치가 필요합니다. 브라우저 로그인에는
GitHub CLI가 필요하며, CLI 없이 개인 액세스 토큰을 연결할 수도 있습니다.
토큰 방식은 앱을 재실행할 때 다시 연결합니다. 앱 안에서 연결을 해제해도 GitHub CLI의
기존 로그인 자체를 지우지는 않습니다.

**작업 메뉴 → GitHub · 업데이트**에서 현재 버전과 최신 정식 릴리스를 확인합니다. 실행 파일은
공식 GitHub 릴리스에서 내려받고 SHA-256을 검증합니다. **저장 후 업데이트 적용**은
현재 초안을 저장한 뒤 앱을 종료하고, 기존 파일을 백업한 뒤 새 버전을 실행합니다.
실행 파일이 있는 폴더에 쓰기 권한이 필요합니다. 소스 실행은 Git으로 업데이트하세요.
현재 앱에서 진행 중인 백업·동기화·테마 빌드는 마친 뒤 종료합니다.

## 기존 글, 가져오기, 복구

- 왼쪽 목록에서 제목이나 태그로 검색해 기존 글을 엽니다. 기존 글은 원문 보존을
  위해 Markdown 모드로 시작하며, 제목을 바꿔도 파일 경로와 주소를 유지합니다.
  기존 글의 날짜·주소 이름·카테고리 이동은 이 편집기에서 지원하지 않습니다.
- **Markdown 가져오기**로 UTF-8 `.md` 파일을 새 초안으로 불러옵니다. YAML
  front matter도 읽습니다. Notion에서 내보낸 Markdown도 사용할 수 있지만,
  ZIP 파일이나 함께 내보낸 이미지 폴더를 자동으로 가져오지는 않습니다.
  이미지는 별도로 첨부하세요. 가져올 파일은 4MB 이하입니다.
- **문서 → 내려받기**는 현재 초안을 YAML front matter를 포함한 Markdown 파일로
  내보냅니다. 별도 이미지 ZIP은 포함하지 않습니다.
- **문서 → 기록**에서 최근 50회 저장 내용을 확인하고 복원합니다. 복원도 새 기록으로
  남으며, 원본 파일을 바로 덮어쓰지 않습니다.
- **작성 중**은 로컬에 임시저장한 초안과 기존 글의 수정본을 모아둔 목록입니다.
  각 글 오른쪽 **삭제** 버튼으로 글을 열지 않고 삭제할 수 있습니다.
  글 설정의 **이 초안 삭제** 버튼도 동일하게 동작합니다. `_posts`의 원본 글은
  삭제하지 않으며, 저장 이력과 업로드 이미지는 복구 자료로 남습니다.

다른 탭이나 외부 편집기에서 파일이 바뀌면 저장을 막고 충돌을 알립니다.
먼저 현재 내용을 **내려받기**로 보관하세요. 외부에서 변경된 원본을 다시 읽으려면
현재 초안을 삭제한 뒤 원본 글을 열고 보관한 내용을 반영하면 됩니다.

## 단축키

| 단축키 | 기능 |
| --- | --- |
| `Ctrl/⌘ + S` | 지금 초안 저장 |
| `Ctrl/⌘ + Shift + F` | 집중 모드 |
| `/` | 검색창으로 이동 |
| `N` | 새 글 작성 |

검색과 새 글 단축키는 입력란에서 글을 쓰는 동안 동작하지 않습니다.

## 알아두면 좋은 점

Markdown 편집 영역이 좁으면 **편집 / 미리보기** 탭으로 전환해 본문을 넓게
보여줍니다. 넓은 화면에서는 원문과 미리보기를 나란히 표시합니다.

편집 미리보기는 실제 Jekyll 사이트 전체를 실행하는 화면이 아닙니다. 편집기에서
수식은 KaTeX로 표시하며, 실제 사이트의 MathJax, Liquid, 테마와 결과가 다를 수
있습니다. 수식·Liquid·복잡한 HTML을 포함한 글은 Markdown 모드를 권장합니다.
시각 편집으로 전환하면 일부 Markdown 표현이나 서식이 정규화될 수 있습니다.

본문만 수정하면 기존 YAML 설정의 원문을 유지합니다. 제목·태그 등 설정을
수정하면 YAML을 다시 작성하므로 주석이나 따옴표 모양은 바뀔 수 있습니다.
편집기에 없는 설정 키와 중첩 설정 값은 보존합니다. 기존 `sitemap: false` 같은
편집기 밖의 설정도 유지하므로 필요하면 원본 파일에서 별도로 수정하세요.

카테고리는 선택한 블로그의 `_data/categories.yml`에서 불러옵니다. 예를 들어 메뉴의
`Deep Learning`은 기존 카테고리 페이지에 맞는 `Deep-Learning` 값으로 저장됩니다.
표시명, 폴더 이름, 실제 카테고리 값은 서로 달라도 기존 페이지와 연결을 유지합니다.

도구의 목차·댓글·수식 설정은 글의 YAML에 저장됩니다. 실제 표시 여부는 블로그
테마가 그 설정을 사용하는지에 달려 있습니다. 새 글 날짜는 한국 시간으로
생성됩니다. Jekyll이 미래 날짜의 글을 제외할 수 있어 발행 전 검사에서 미래
날짜의 글 저장을 막습니다. 예약 발행 서비스는 제공하지 않습니다.

편집기와 수식·글꼴 파일은 저장소에 포함되어 있어 오프라인으로 사용할 수
있습니다. 외부 URL의 이미지와 GitHub 전송에는 인터넷이 필요합니다. GitHub 인증은
**GitHub · 업데이트**에서 연결할 수 있습니다. 브라우저 로그인은 설치된 GitHub CLI를
사용하며, 토큰 연결은 현재 앱의 메모리에만 토큰을 보관합니다. 같은 메뉴의
**Git 작성자 설정**으로 현재 블로그의 이름과 이메일을 설정할 수 있습니다.

다른 작업이 스테이징되어 있으면 커밋·전송을 중단합니다. 원격에 새 변경이 있거나
이 글과 무관한 미전송 커밋이 있으면 GitHub 전송을 중단합니다. 터미널에서 기존
작업을 확인하고 동기화한 뒤 다시 시도하세요. 전송만 실패한 경우 로컬 파일과
커밋은 남으므로 같은 글에서 전송을 다시 시도할 수 있습니다.

## 로컬 파일과 유지보수

| 경로 | 내용 |
| --- | --- |
| `.blog-studio/drafts/<id>.json` | 자동 저장 초안 |
| `.blog-studio/history/<id>/` | 최근 50회 저장 기록 |
| `.blog-studio/uploads/<id>/` | 초안에 첨부한 원본 이미지 |
| `.blog-studio/backups/<id>/` | 기존 글을 변경하기 직전의 Markdown 백업 |
| 프로그램 폴더의 `.venv/` | 소스 실행용 Python 환경 |
| `_posts/<카테고리>/<날짜>-<주소>.md` | 발행 준비에서 저장한 글 |
| `assets/images/posts/studio-<id>/` | 저장한 글에 사용하는 이미지 |

`.blog-studio`는 블로그의 Git과 Jekyll 게시 대상에서 제외해 주세요. 컴퓨터를 옮길 때 초안과
기록을 유지하려면 **백업·동기화**를 이용하세요. 이력 50회 제한 외에는 업로드와
백업 파일을 자동 정리하지 않습니다. 프로그램은 별도 폴더에 두세요. 선택한 블로그의 `.gitignore`와 Jekyll 제외 설정은 직접 유지해야 합니다.

서버는 `127.0.0.1`에서만 실행됩니다. 다른 웹사이트의 API 호출과 임의 파일 경로
접근을 막고, HTML 정화와 CSP를 적용합니다. TOAST UI Editor 3.2.2와 별도
DOMPurify 3.4.16을 사용합니다. 의존성 업데이트 시 수식과 기존 Markdown 보존을
다시 검증해야 합니다. 원본 배포 주소, 버전, 라이선스와 파일 해시는
[vendor 안내](../static/vendor/README.md)와 [manifest](../static/vendor/manifest.json)에 있습니다.

Ubuntu/Debian에서 소스 실행용 `venv` 생성 오류가 나면
`sudo apt install python3-venv` 후 다시 실행하세요. 데스크톱 실행 파일에는
이 과정이 필요하지 않습니다.
